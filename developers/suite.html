The various GNUstep libraries and tools that will be used mainly by developers are described here. Also look here for Progress on the libraries and tools.

The Core

It's the core set of libraries and tools which forms the basis for what programmer's joyously proclaim: GNUstep! Going beyond the strict OpenStep specificiation, GNUstep is a complete, integrated development environment with support for cross-compiling, multiple architectures, and multiple OpenStep implementations designed in the framework from the start (at least we hope it will be that way).

GNU Objective-C Compiler (gcc)

To be able to produce the desired applications one has to make executable binaries out of the code. The GNU C compiler has supported Objective-C for a long time now, and it has been ported to almost every operating system.

GNU Debugger (gdb)

With special patches for debugging Objective-C code.

GNUstep Makefile Package (gnustep-make)

The GNUstep Makefile Package is centralized configuration mechanism and a set of powerful makefile rules that makes compilation of GNUstep source as easy as just listing the files to compile. Read the design document for a more detailed discussion of the design goals and implementation.

GNUstep Base Library (gnustep-base)

The GNUstep Base Library implements the FoundationKit portion of the OpenStep specification. It has as its heritage the libobjects library; a set of general-purpose, non-graphical Objective-C classes designed in the Smalltalk tradition, and was written by Andrew McCallum. The library has since been greatly enhanced by Andrew and many other contributing developers to be a fairly complete FoundationKit implementation; it still contains the extensive collection classes from the original libobjects library.

Display Ghostscript System (dgs)

The Display Ghostscript System is needed on operating systems which do not have the Adobe Display PostScript System. Most commercial UNIX systems by Sun, HP, IBM, Digital come with Adobe's DPS as part of the X Window System. The Linux/GNU operating system, however, is one major exception, so the GNUstep developers have decide to create their own implementation that is royalty-free and freely distributable.

GNUstep GUI Library (gnustep-gui)

The GNUstep GUI Library implements the ApplicationKit portion of the OpenStep specification.

GNUstep X/DPS GUI Backend (gnustep-xdps)

The GNUStep X/DPS GUI Backend is the backend implementation for the GNUstep GUI Library on operating systems with the X Window System and the Display PostScript System.

X11 Backend with Drawing Engine (gstep-xgps)

The X11 GPS Backend is a back-end library that uses only X11 calls for drawing (no Postscript). It also has a Drawing Engine which tries to emulate common PostScript functions.

Related Projects

libFoundation

An implementation of the OpenStep FoundationKit, therefore a potential replacement for gnustep-base. libFoundation is more slim than gnustep-base, but still lacks a few features of Foundation. It implements some extensions to Foundation that are also available separately for use with gnustep-base or NeXT's FoundationKit. Both the library and extensions are available at the above named GNUstep ftp sites.



ToolStory

A clever and portable library is worth little (or nothing) as long as there are no tools that will help a potential developer to understand the system and get things running the way they were meant to be. Some people might be satisfied with using Emacs and a set of command line tools while others are asking for better interfaces to the complex development process. We are aware of this fact and some people have started working on applications that are necessary to provide a complete development environment.

Most of the tools mentioned here should be interesting to every OpenStep implemenation as they are/will be portable and therefore can extend or replace other OpenStep development environments. So the time frame for these applications is not necessarily related to that of a GNU OpenStep implementation.

ProjectCenter

The heart of a development system is always some kind of project management. From here you should be able to search, edit, debug and design your classes with a variety of tools.

InterfaceModeller

To be correct one should call this an ObjectModeller because such an InterfaceModeller will let you build a graph of objects by connecting their interfaces (which mostly are user interface classes). The instance variables of these objects can be assigned to references or target/action before they get archived into a file. At least this is what NeXTs InterfaceBuilder is doing and what we are trying to provide in a free implementation.

Debugger

Since writing applications...even under OpenStep...is always troubled; to find and fix the errors one has made, we need a debugging tool. The GNU gdb is not as easy to port as the compiler (because it has to deal with more hardware/OS internals) but should be available for most platform anyways.
