User Suite

One of the reasons why GNUstep got started was the longing for the ease of programming and the ease of use which we feel is not available under other operating systems. However to take GNUstep out of the realm of programmers and make it more accessible to average users; there is a definite need to provide a set of standard applications. There aren't any standard applications written with GNUstep, but there are several that are meant to be used with GNUstep or are related to it. These include:
WindowMaker
WindowMaker is a window manager with a nice NeXTStep look and feel that is meant to support GNUstep applications.
GNU Yellow Vector Editor (GYVE)
GYVE is an extensible vector-based drawing package in the spirit of Adobe Illustrator. GYVE uses Display PostScript for drawing (Display Ghostscript on systems that don't have native DPS).

Related Projects

  • AfterStep is another NeXT-like X Window manager. Based on fvwm, AfterStep has got quite popular in the meantime. Interest has been expressed from both sides to make AfterStep the window manager of choice for X11.
  • TkSTEP is a replacement for the Tk widget set. If you use TkStep, normal Tk applications look a lot more NeXTish.
  • neXtaw is a replacement for the Athena (libXaw) widget set. Its goal is to try to emulate the look and feel of the NEXTSTEP GUI.
Some of the currently available NeXTSTEP applications could serve as the basis for our user suite.

  • Librarian.app; a more organized means of search and viewing documentation.
  • Ink.app; the GNUstep text editor.
  • Installer.app; the GNUstep installer application for adding/removing packages.
  • VT100.app; the "cannot live without" application for shell access.
  • Scheduler.app; the GNUstep personal information manager for keeping tracking of people, places, dates, times, schedules, and projects.
  • Dictionary.app; the GNUstep interface to the GNU Dictionary Project.
  • GNUMail.app; you really don't expect me to use pine or elm do you?
  • Bank.app; balance your checkbook with style and grace.
  • Chess.app; what would GNUstep be without GNU chess?
  • Fractal.app; watch the beauty of chaos bloom on your GNUstep machine.



Design Matters

Without the underlying framework, it is hard to write an application. But what we can do at this time is to start thinking, painting, and dreaming.

So besides some thoughts about the look'n'feel of GNUstep, we might start talking about the look of individual applications. To spur interest; we encourage you to visit our frequently updated Design Gallery where you can get the first impression of the icons which will be used in the final applications.

Any comments are welcome and should be made on the regular discussion mailing list so we can perform some kind of voting for the visual appearance of GNUstep. Suggestions for new applications and queries about how to get involved in the development process are also encouraged.


GNUstep Workspace

There are currently no fixed plans for the GNUstep Workspace; OpenStep has the notion of a Workspace (by providing a class with such a name) which requires at least an application for the control of the background tasks that the workspace should be performing. These tasks usually include filesystem operations and the like.

For example the SpiderWoman application resembles the look & feel of the NeXTSTEP workspace but extends it to the whole Internet (WWW, Ftp, etc.). Since there is a chance that the sources will be free someday, it would be a perfect place to start.

To make it a killer workspace, we would have to:

  • Add fileystem handling
    The NSFile and MiscFile code would be a good place to start for that part. This would include viewers for browsing and searching the files and directories on the system.

  • Add the notion of processes
    It would need to be able to list and kill processes like Workspace.app does; maybe even provide accounting information like CPU and memory usage.

  • Add drag/drop capability
    There should be some standard protocol for dragging and dropping files; along with this is the ability to double-click on a document, and the application for that document type is automatically executed.

  • Implement a GNU IconKit
    Since the SpiderWoman's code is heaviliy based on the IconKit there would be a need for a reimplementation of its protocols and APIs under the GNU license. During this process the GNU IconKit should switch to using the NSNotificationCenter and drop its current way of notifying listeners.

Besides this generic workspace there is a hack called TheShelf which will try to implement the idea behind NeXT's shelf for OpenStep 4.0. And there are lots of other applications (like the large number of dock-extenders) that would make a good workspace addition or could serve as the "center" of the system.




The Zen of no UI

With all these possible "workspaces" we might ask ourself a simple question:
"Why don't we just write a GNU-DO based WorkspaceMaster which could perform all the necessary tasks like copying files, killing apps, checking for removable media etc. pp. and then just use the NSWorkspace class plus some new notifications to handle the workspace task ?"

This approach would enable the enduser to choose the frontend he likes best, while ensuring that the "dangerous" work is handled by a common piece of code with known behavior (and problems). For the GNU community it seems to be the more reasonable appoach; building a "Master with no UI".
